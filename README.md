# GPU-Accelerated OCR with Qwen3.5-4B

**Lablab.ai × AMD AI Academy Challenge Mini Challenge 2: Image OCR**

A containerized OCR application that extracts text from images using Qwen3.5-4B, PyTorch, Hugging Face Transformers, and AMD ROCm.

## Project Overview

This project demonstrates GPU-accelerated text extraction from images using a vision-language model. The application accepts an image path, processes it through the model, and saves the recognized text as structured JSON.

The solution is packaged in Docker using the ROCm PyTorch base image specified by the challenge.

## Key Features

- **Image-to-text extraction:** Recognizes text in image inputs.
- **Vision-language model:** Uses Qwen3.5-4B.
- **GPU inference:** Uses PyTorch with AMD ROCm.
- **Containerized deployment:** Packages the application and dependencies in Docker.
- **Structured output:** Saves recognized text as JSON.
- **Model reuse:** Uses a worker process intended to load the model once and reuse it for multiple requests.
- **Command-line interface:** Accepts an image path through an argument.

## Getting Started

### Prerequisites

- Docker
- An AMD GPU supported by the selected ROCm environment for GPU inference
- The required ROCm PyTorch base image
- Access to the Qwen3.5-4B model files if they are not included in the Docker image

### Pull the Docker Image

The published image is available on Docker Hub:

**Docker Hub:** https://hub.docker.com/r/samiullahdock/ocr-challenge

```bash
docker pull samiullahdock/ocr-challenge:v1
```

### Run OCR

The challenge-compatible command is:

```bash
python3 /app/app.py --input-image /app/input/image_01.png
```

The application is expected to save the output as:

```text
/app/output/image_01_output.json
```

The JSON file contains the extracted text and may contain a confidence field.

The challenge evaluator runs the application inside its prepared container environment.

## Performance and Evaluation

One observed test successfully extracted `7ABC123`. A subsequent command completed in approximately 5.3 seconds.

This timing is a single observed execution, not a controlled benchmark. It should not be treated as a general latency guarantee.

A complete evaluation should measure:

- Recognition accuracy across a representative set of images
- End-to-end processing time per image
- Model initialization and cold-start time
- Peak GPU memory usage
- Performance across different image formats and resolutions
- Reliability on noisy, rotated, or low-resolution text

No overall accuracy percentage or throughput claim is made without further testing.

## Limitations

- OCR quality depends on image resolution, text size, font, orientation, and image quality.
- One successful sample does not establish general accuracy.
- Confidence values may not represent calibrated probabilities.
- More testing is needed to establish robustness and performance across varied inputs.
